## What was built

### hw-hydrogen-storefront-node-docker
- `app/lib/cookieConsent.server.ts` — a **dedicated, long-lived** `cookie_consent`
  cookie (httpOnly, sameSite=lax, maxAge=1 year, signed with SESSION_SECRET),
  deliberately NOT piggybacked on the existing ambient `session` cookie
  (app/lib/session.ts), which has no maxAge and disappears when the browser
  session ends — POPIA requires the choice to persist across return visits,
  not just the current session. Also exports `syncCookieConsentToBackend` /
  `fetchCookieConsentFromBackend` (the cross-repo calls) and `buildCookieConsent`.
- `app/routes/cookie-consent.tsx` — resource route (`/cookie-consent`, no UI),
  action-only: sets the cookie for every visitor (anonymous or logged in) and,
  if `customerAccount.isLoggedIn()`, additionally syncs to the backend
  (best-effort, non-blocking — the cookie is always the source of truth for
  whether the gate shows).
- `app/root.tsx` — loader parses the cookie synchronously (no network call)
  into `cookieConsent`, returned alongside the existing critical/deferred data
  so `PageLayout` gets it without a Suspense flash. Also mounts a new
  `<CustomerPrivacySync>` inside `<Analytics.Provider>` to push the choice into
  Shopify's own Customer Privacy API (see "Follow-up" below for the one manual
  step this needs in Shopify Admin).
- `app/components/CookieConsentGate.tsx` — the banner. First-visit / no-cookie
  state is **non-dismissible** (no Escape/backdrop/X — deliberately different
  from the existing `ContentModal`/`GalleryCarousel` full-screen-overlay
  pattern it otherwise reuses) until Accept All / Reject Non-Essential / Manage
  Preferences+Save is submitted. When reopened from the Footer link (consent
  already exists), the same component becomes dismissible (X, Escape, backdrop
  click) since site use isn't blocked anymore.
- `app/components/PageLayout.tsx` / `app/components/Footer.tsx` — wired via
  plain lifted `useState` + props (matching this codebase's existing
  prop-drilling convention for cart/footer/settings, not a new context) rather
  than introducing a new provider: `PageLayout` holds `managePreferencesOpen`,
  passes it to the gate and an `onOpenCookiePreferences` opener to `Footer`'s
  new "Cookie Preferences" button (sits next to the existing Image Credit /
  policy links).
- `app/routes/account.cookie-preferences.tsx` + `account.tsx` nav link — the
  amendment page for logged-in customers, structurally a direct copy of
  `account.profile.tsx`'s loader/action pattern (backend fetch with a
  cookie-value fallback for a first-time-on-this-device case, then an
  intent-less single-purpose action that updates both the cookie and the
  backend record).
