### Investigation (debug mode)

Confirmed via code read (app/components/CollectionCard.tsx, app/routes/($locale).collections.$handle.tsx, app/styles/app.css/reset.css) that Tier 2/3 tiles already reuse the SAME `CollectionCard` component and `.collections-grid`/`.collection-item*` CSS as the Tier 1 homepage grid — there is no separate/duplicate markup for Sub Collection or Sub-Cat Collection tiles (this unification was built out in earlier sessions 2607271000/2607271300/2607271535). So the reported visual mismatch in the three error screenshots was a genuine styling bug in the SHARED component/CSS, not a missing feature.

**Root cause (confirmed live, not guessed):** `app/styles/app.css` has a sitewide rule (line ~86, added in an earlier session to fix a DIFFERENT bug — redundant nested boxes on product/page headings):
```css
.page-card h1, .page-card h2, .page-card h3, .page-card h4, .page-card h5,
.product-card h1, ... {
  background: none; padding: 0; border-radius: 0; width: auto; max-width: none;
}
```
`SubCollectionsView` in `($locale).collections.$handle.tsx` (the component that renders Sub/Sub-Cat Collection tiles on a Main/Sub collection detail page, e.g. `/collections/power-products`, `/collections/household`, `/collections/welding`) wraps its `.collections-grid` in `<div className="page-card page-card--wide">`. That blanket override strips the sitewide dark chip (`rgba(50,50,50,0.85)` background, from reset.css's `h1-h5` rule) from `CollectionCard`'s own title heading — even though each tile's background is its OWN image, not the page-card's, so it still needs its per-tile chip.

The Tier 1 homepage grid (`($locale)._index.tsx`) is NOT wrapped in `.page-card` (confirmed by grep — no `page-card` anywhere in that route file), which is exactly why it was unaffected and looked correct in `260728084144-errors.png` while Tier 2 (`260728084157`/`260728084207-errors.png`) showed plain white tiles with poor-contrast overlaid text (the "Machines & Built Units"/"Home ware" text overlapping unreadably against light product photos).

Secondary, smaller gap found in the same investigation: `.collection-item-title-wrap h2, h3 { margin:0; text-align:center; max-width:100% }` never included `h4` — the heading level `computeChildTier()` hands out for Sub-Cat tiles (e.g. the `/collections/welding` sub-cat grid) — so those tiles kept the dark chip (from bare reset.css, since `/collections/welding` IS wrapped in `.page-card` too, so this was actually ALSO broken by the same root cause) but weren't centred by this rule once restored.

### Fix Applied

File changed: `app/styles/app.css` only.

1. Added `.collection-item-title-wrap h4` to the existing centering rule (was h2/h3 only).
2. Added a new, higher-specificity rule directly below it that restores the dark chip specifically for `CollectionCard` titles nested inside `.page-card`:
```css
.page-card .collection-item-title-wrap h2,
.page-card .collection-item-title-wrap h3,
.page-card .collection-item-title-wrap h4 {
  background: rgba(50, 50, 50, 0.85);
  padding: 0.5rem 0.75rem;
  border-radius: 6px;
  width: fit-content;
  max-width: 100%;
  color: rgba(255, 255, 255);
}
```
   Specificity (0,2,1) beats the offending `.page-card h3` rule (0,1,1) regardless of source order, so no need to reorder/!important.
3. Updated two stale comments (one above `.collection-item-media`, one above the original `.page-card h1..h5` override reasoning is unchanged/still valid for its original purpose) to document the new interaction so a future session doesn't reintroduce a blanket `.page-card h1..h5` fix without carving out this exception again.

No component/JSX changes needed — the existing `CollectionCard.tsx`/`SubCollectionsView` architecture was already correct; this was a pure CSS cascade bug.
